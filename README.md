# 《未知进化》创作工作区

这是末日生态进化科幻网文《未知进化》的创作仓库。主线从南京仙林校园灾变开始，经千里返乡、绵德防线、成都控制区与盆地退潮，最终抵达柴达木低能耗生物库。

本书不是无限流、灵异副本或系统升级文。核心机制是迁跃体加速真实生物试错；所有强化都受能量、结构、繁殖和生态位约束。

## 按任务读取

不要每次把全部文档喂给 AI。建议按任务读取：

- 调整人物、七卷剧情、能力或结局：`CLAUDE.md` + `未知进化_故事总纲.md`。
- 调整迁跃机制、人类表型或庇护城：再读 `未知进化_世界设定.md`。
- 调整返乡、成都或高原路线：再读 `未知进化_地理路线.md`。
- 设计具体遭遇与生态链：再读 `未知进化_物种图鉴.md` 中相关区域。
- 写单章：对应卷纲 + 当前地点/物种 + 章节细纲 + 前一章正文。
- 改连续章节：目标范围之外至少多读前一章与后一章细纲或正文。

若当前卷细纲、章节细纲或 `正文/` 尚未建立，AI 必须明确以现有总纲为依据，不能假装读取了不存在的文件。

## 正文最高原则

本书首先向读者展示奇异新世界和林扬的挣扎，不把正文写成生态论文、证据陈列或正确解题过程。

- 底层保持人物位置、伤势、资源、能力和基本因果连续，正文不展示这套检查过程。
- 读者需要看懂人物为何行动，不需要看完观察、证据、推理和结论的完整链条。
- 新生命先可以美、怪、壮观、有用或令人不适，不必一登场就攻击人类。
- 生态链不按“血腥生命加身体恐怖生命”逐项配额；全书同时保留捕食、寄生、竞争、漠不关心和互利共存，前期重点展示物种之间的残酷猎杀。
- 暴力重在动作清楚、后果具体和形式新奇。华丽反差来自生物外形与行为，正文句子仍须通俗直接。
- 开篇核心物种不能只当作环境压力和事故诱因。前三至六章必须尽早完成一次主动、近距离、有物种辨识度的猎杀；未知可以暂不解释机制，不能把接触、肉体破坏和死亡一起藏掉。
- 场景连续、单一压力线、贴身视角和通俗语言不等于降低事件强度。同一麻烦要在场内持续升级并付出代价，不能只增加声音、影子、咳嗽和逼近中的威胁。
- 林扬观察路线、裂缝、花粉和水源，是因为要回家、逃命、救人，或被眼前奇异生命吸引，不是为了给读者证明设定。
- 允许人物听错、误判、冲动、逃避和选择非最优方案；未知可以跨越多章，甚至不完全解释。
- 默认每章最多确认一个新生态结论；首次登场不同时说明物种机制、弱点、研究名和用途。
- 强画面、关键动作和具体后果之后直接推进，删掉“这意味着”“他意识到”式翻译。
- “三次见面”“误读、观察、准备、接触”只用于幕后设计，不得成为正文打卡模板。
- 第三人称限知不只是“不写林扬不知道的信息”，还要让每句现场叙述从他的感官、身体、念头、动作或误解中发生。
- 禁止用外部摄像机先替林扬看清完整现象，再写他的反应；也不用高频“他看见”“他觉得”来假装贴身。
- 信息属实、林扬可知，不等于必须写进本章。只写能改变他当场欲望、注意、身体、动作、选择或关系的信息。
- 每章只让一条主要异常或压力线升级。新闻、群聊、报告、远方消息和新物种不得并列摆证据；不能加深同一异常或改变林扬行动的，延后到下一章。
- 正文只用通俗、直接的现代汉语。普通动作写清谁做了什么，不用陌生搭配、抽象意象、拟人化气味和光线制造小说感；奇异感由新世界本身承担。
- 对白要像普通人在现场说话，允许抢话、重复、说不完整和没听清，不把人物台词修成完整观点或漂亮金句。

正文任务可以统一附加：

```text
底层保持连续性与基本因果，但不要在正文中展示推理链和设定证明。正文只负责让读者贴着林扬经历奇观、欲望、误判、行动、挣扎和后果。

贴近林扬不是用外部摄像机跟拍他。每句现场叙述都必须从他此刻的感官、身体、念头、动作或误解中发生。只报告“他做了什么”也不算贴身，动作要带着他的目的、阻力、身体感或注意变化发生。不先由旁白宣布完整异常、再写他发现；不写他看不见的全景、背影和未察觉的身后动静；不靠句句重复“他看见”“他觉得”来标记视角。

设定可以在大纲中完整存在，正文只写此刻真正撞到林扬身上的部分。信息可知不代表必须写；它必须改变他当前的欲望、注意、身体、动作、选择或关系。每章只维持一条主要异常或压力线；新闻、通知、群聊、报告、远方消息和新物种只能加深它或迫使林扬改变行动，不得并列摆证据。

新物种首次出现不解释完整机制、弱点、研究名和资源用途；每章默认最多确认一个新生态结论。人物允许听错、漏看、冲动和做出非最优选择。

强画面或关键动作已经传达信息时，停在画面上，不追加“这意味着、这说明、显然、由此判断、真正的原因是、换句话说”等总结。写完删除不影响下一步理解的分析句、解释句和证据链。

全文使用通俗、直接的现代汉语。能直接写疼、喘、滑、撞、卡住和灯灭，就不用抽象意象、生造搭配、拟人化气味或光线增加文艺感。比喻只在帮助读者看清形状、距离和动作时保留。对白按普通人在现场的说话方式写，允许重复、没说完和答非所问，不写主题句与可摘抄金句。
```

## 推荐工作流

### 1. 先建卷级约束

写新卷前先确认：

- 时间与地点；
- 核心生存目标；
- 生态阶段和核心物种；
- 林扬当前能力、升级节点、首秀、代价和身份回报；
- 核心配角在本卷的长期价值与冲突；普通同行者无需逐个设计用途；
- 小兑现、中型兑现和卷末公开大兑现；
- 本卷夺回或失去的路线、设施、资源和知识。

### 2. 再做章节卡

章节卡至少记录：

```text
时间地点 / 视角 / 起始状态
本章唯一主目标 / 当场压力
物种痕迹 / 旧经验误判 / 观察来源
准备与失败方案 / 林扬关键动作 / 核心配角必要动作（本章如有）/ 普通同行者即时反应
获得与损失 / 生态后果 / 生理债连续性
章末具体钩子
```

同一生态事件可跨章完成“误读、观察、准备、接触”，不要把它机械压进每一章。

章节卡是幕后连续性账，不要求字段逐项进入正文。生态事件需要产生行动结果，但其机制不必完整闭环。

### 3. 正文串行推进

正文按连续章节串行创作。每一批完成后先检查：

- 上章后果是否接住；
- 人物位置、伤势和同行关系是否连续；
- 食水、装备、车辆、设施和通信是否守恒；
- 林扬是否使用了当前卷允许的能力；
- 物种弱点是否有前置观察，优势是否支付结构代价；
- 专业配角是否真正完成了自己的工作；
- 胜利是否得到可见回报，生理债是否在合适场面结算；
- 章末钩子是否由本章后果自然产生。

检查通过再写下一批，避免把连续性问题积累到整卷末尾。

### 4. 去 AI 味放在事实检查之后

先修事实、因果、动作空间和人物动机，再处理句式。去 AI 味不能删掉：

- 林扬的关键判断与最后接触；
- 物种痕迹、结构代价和生态后果；
- 团队专业分工；
- 明确的胜利、损失、资源与权限变化；
- 生理债和下一章接力。

```text
请先读取 CLAUDE.md、未知进化_故事总纲.md，并按问题需要读取世界设定、地理路线和物种图鉴。审查【目标文件/主题】与当前设定的一致性。

按严重度优先检查：
1. 时间、人物、能力阶段和七卷顺序；
2. 迁跃的能量来源、结构代价和繁殖速度；
3. 地理路线、交通节点和跨区关系；
4. 物种生态链、弱点来源和资源用途；
5. 人物动机、团队专业价值和主题偏移。

先给出带文件位置的具体问题，再给最小修订方案。不要修改拆分前完整归档。
```

### 设计当前卷章节细纲

```text
使用 webnovel-workflow，读取 CLAUDE.md、未知进化_故事总纲.md 中第【X】卷、当前卷涉及的地理路线、世界阶段和物种条目，为第【起始章】-第【结束章】设计章节细纲。

要求：
- 每章只有一个主要推进目标；
- 每章只有一条主要异常或压力线，新信息必须加深它或改变林扬的当场行动；
- 同一生态遭遇按“痕迹、误判、接触”逐步展示；
- 冲突整体完成“误读、观察、准备、接触”，但不机械要求每章四步俱全；
- 林扬能力严格服从当前卷阶段；
- 核心配角在整段剧情中应有林扬无法长期替代的价值，但不要求每章、每次出场都发挥作用；
- 普通同行者和一次性路人可以没有专业能力、剧情功能、成长线与后续回收，不强行命名、分配技能或安排报恩；
- 记录人物位置、伤势、食水、装备、车辆、通信和生理债；
- 每次胜利产生具体回报和生态后果；
- 章末钩子来自本章因果。

完成后检查与后一阶段的接力，并同步真正受影响的工作文件。
```

### 串行创作正文

```text
请依据项目总规则、对应卷纲、章节细纲、登场物种设定，以及相邻已完成正文，
  串行创作【第X章】至【第Y章】。

  严格按“一章创作 -> 一章复核 -> 修正后再写下一章”的方式执行，不要一次性批
  量写完所有章节，也不要只给细纲或创作计划。

  每章流程：

  1. 先读取上一章结尾、当前章细纲和下一章的接力需求。同时明确本章给网文读
     者的核心追读兑现是什么：新奇画面、主动猎杀、主角高光、残酷选择、明确损
     失或局势突变。本章可以不把所有类型都写全，但不能只有铺垫和气氛。
  2. 在不输出计划的前提下，先按现场划分本章。一个现场只围绕主角眼前的一件
     麻烦：从他正在处理的动作进入，直到这个动作得到具体结果、失败，或被一个已
     经发生的变化彻底打断，再进入下一个现场。下一个现场必须从前一个现场末尾的
     人物位置、身体状态、物件或新变化自然长出来，不能为了完成细纲节点突然切到
     新地点、新危机或新人物。场景连续只约束画面如何衔接，不限制事件强度；同一
     麻烦应从出现、逼近继续升级到接触、伤害、失败或代价，不能反复增加细节却让
     局势不变。
  3. 只创建当前这一章正文，保持贴近主角的第三人称限知视角。宁可少写一个细纲
     事件、延后到下一章，也不要把关光、逃跑、遇人、发现新物种、能力首秀、路线
     选择等多个完整画面挤进同一章或同一场面。不要把细纲逐条改写成正文。
     若本章承担前期核心物种首次正面威胁，必须让该物种成为行动者，而不是气味、
     粉尘、声音、黑影或踩踏事故的背景。至少完整写出一次“靠近或选择活人 -> 发
     生身体接触 -> 以该物种独有方式破坏肉体 -> 留下不可逆后果”的动作链。机制
     和来源可以继续未知，已经发生的扑击、穿刺、吸血、撕裂、寄生或死亡不能含蓄
     带过、移到门外或只用惨叫交代。
  4. 写完立刻复核本章：
     - 是否从主角正在处理的具体麻烦进入；
     - 是否只有一条主要压力线；
     - 本章是否真的兑现了一项值得继续追读的内容，而不只是为以后铺垫；删除本章
       后如果只少了一段移动、气氛或“危险越来越近”，说明强度不足；
     - 每个场面是否真正停留到当下动作完成或被打断，而不是刚看清一个画面就跳去
       交付下一个细纲事件；
     - 同一场面的压力是否改变了人物身体、位置、物件、选择或生死，而不是只增加
       翅响、影子、咳嗽、围观和更近的距离；
     - 场面转换时，读者是否能跟着主角看清从哪里到哪里、谁还在身边、手上拿着什
       么、前一刻发生的事怎样逼出下一步；
     - 是否所有画面、判断、动作都贴着主角当场感受发生；
     - 是否避免旁观者全景、作者总结、设定讲解、证据链和 AI 式论证；
     - 是否使用通俗直接的描写与对白，不写文青式比喻和漂亮话；
     - 是否把“通俗、克制、近视角、场景厚度”误写成平淡；句子可以朴素，事件必
       须保留应有的暴力、猎奇、恐怖和冲击；
     - 核心新物种是否亲自行动并造成有辨识度的伤害；血腥是否来自它的身体结构和
       捕食方式，而不是主要由踩踏、桌椅、门板和远处惨叫代替；
     - 未知感是否只保留未知机制，而没有藏掉读者此刻应看到的攻击、人体损伤与死
       亡兑现；
     - 对白是否只来自人物当场要人、要路、要药、要自保或失控的反应，而不是替作
       者报方向、解释风险、介绍人物、切换场景或替下一章摆钩子；
     - 是否删掉了过于准确、轮流接话、恰好说出局势结论的台词；危机中的人可以听
       错、重复、说半句、不回答，能用动作、位置和物件写清的事不让角色再说一遍；
     - 是否让配角通过当场行动存在，而不是轮流发表观点；
     - 是否与前章的人物位置、伤势、装备、资源、时间和物种信息连续；
     - 是否准确把新的动作、风险或选择交给下一章。
  5. 发现问题时，先修改当前章，再进入下一章；不要带着已知问题继续写。
  6. 当前章复核通过后，自动创作下一章，重复上述流程，直到完成指定范围。

  正文优先写主角此刻想做什么、眼前有什么阻碍、他如何行动、行动造成什么后
  果。新世界和新物种应通过主角亲历的画面、身体反应和实际损失进入，不要为了
  展示设定而堆砌信息。章节细纲只规定必须守住的事实和结果，不规定正文必须逐项
  展示；正式正文应先让一个画面在主角眼前成立，再由画面本身把他推到下一个画面。
  贴近主角不等于把最狠的部分挡在视野外，未知也不等于只写危险接近。尤其在开篇
  阶段，应让主角近距离看见、碰到并处理新物种造成的血、伤口、尸体与救援失败，
  让读者先确认这个新世界真的会杀人，再逐步揭开它为什么这样运转。

  全部章节完成后，只简要报告：
  - 创建的正文文件；
  - 每章的核心推进；
  - 每章的追读兑现，以及核心新物种是否完成主动、可见、有辨识度的伤害；
  - 连续性与文风复核结果；
  - 是否存在未提交改动。

  全部章节复核通过后，自动提交本地仓库，并报告提交号。
```

先锁定不可误改的剧情事实：路线、人物在场、伤势、装备、食水、车辆、通信、林扬能力阶段、物种痕迹与弱点、胜利回报、生理债和章末钩子。

## 番茄草稿箱上传工具

本项目提供一个浏览器自动化工具，用于把根目录 `正文/` 下的正文章节保存到番茄小说作者后台草稿箱。

> 注意：`fanqie_draft_upload/fanqie_publish.yaml` 当前仍保留上一作品的 `book_name` 和后台地址。在取得《未知进化》的作品 ID 并人工更新配置前，不要执行远端保存命令。

功能边界：

- 只保存草稿，不发布、不定时发布、不提交审核。
- 不在项目中保存账号、密码、cookie 或 token。
- 浏览器登录状态保存在仓库外，具体路径以 `fanqie_publish.yaml` 为准。
- 工具只读取 `正文/` 并写入本地状态台账，不移动、不改写小说创作文件。

相关文件集中在：

```text
fanqie_draft_upload/
├── fanqie_prepare_manifest.py      # 生成/刷新章节状态台账
├── fanqie_publish_browser.py       # 打开番茄后台并保存草稿
├── fanqie_publish.yaml             # 番茄后台地址、选择器、路径与安全配置
├── requirements.txt                # Playwright/PyYAML 依赖
└── data/fanqie_publish_state.json  # 本地章节状态台账，不提交
```

### 安装依赖

```bash
pip install -r fanqie_draft_upload/requirements.txt
python3 -m playwright install chromium
```

### 首次登录番茄后台

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py login
```

脚本会打开浏览器。请手动完成番茄作者后台登录、验证码、短信或滑块验证。

### 生成或刷新章节台账

```bash
python3 fanqie_draft_upload/fanqie_prepare_manifest.py
```

默认读取根目录 `正文/`，生成：

```text
fanqie_draft_upload/data/fanqie_publish_state.json
```

如果某章已标记为 `draft_saved`，但本地正文 hash 已变化，脚本会停止并要求先人工确认远端草稿，避免覆盖不明状态。

### 检查后台页面

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py check
```

用于确认脚本能进入对应作品的章节管理/草稿箱页面。

### 审核待上传章节

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py audit
```

该命令只读取本地状态台账，输出各状态章节数量和章节范围，不会打开远端保存草稿。

### 保存章节到番茄草稿箱

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py save-drafts --confirm-save-drafts
```

常用范围参数：

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py save-drafts --start 1 --end 10 --confirm-save-drafts
python3 fanqie_draft_upload/fanqie_publish_browser.py save-drafts --only-chapter 12 --confirm-save-drafts
python3 fanqie_draft_upload/fanqie_publish_browser.py save-drafts --limit 3 --confirm-save-drafts
```

真正写入远端草稿箱前，脚本还会要求输入确认语，例如：

```text
SAVE FANQIE DRAFTS 1-10
```

确认语不匹配会取消操作。

### 中断后继续

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py resume --confirm-save-drafts
```

如果出现 `draft_saving` 遗留状态，应先人工确认番茄后台草稿是否已保存，再手动把对应章节状态改回 `pending` 或标记为 `draft_saved`。

### 日志、截图与本地状态

运行截图和错误截图默认保存在：

```text
fanqie_draft_upload/logs/
```

这些运行产物和本地状态台账已在 `.gitignore` 中忽略，不应提交到仓库。
