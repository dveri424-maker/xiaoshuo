# 《未知进化》创作工作区

这是末日生态进化科幻网文《未知进化》的创作仓库。主线从南京仙林校园灾变开始，经千里返乡、绵德防线、成都控制区与盆地退潮，最终抵达柴达木低能耗生物库。

本书不是无限流、灵异副本或系统升级文。核心机制是迁跃体加速真实生物试错；所有强化都受能量、结构、繁殖和生态位约束。

## 按任务读取

不要每次把全部文档喂给 AI。建议按任务读取：

- 调整人物、七卷剧情、能力或结局：`CLAUDE.md` + `未知进化_故事总纲.md`。
- 调整迁跃机制、人类表型或庇护城：再读 `未知进化_世界设定.md`。
- 调整返乡、成都或高原路线：再读 `未知进化_地理路线.md`。
- 设计具体遭遇与生态链：再读 `未知进化_物种图鉴.md` 中相关区域。
- 写单章：对应卷纲 + 当前地点/物种 + 章节细纲 + 前一章正文。
- 改连续章节：目标范围之外至少多读前一章与后一章细纲或正文。

若当前卷细纲、章节细纲或 `正文/` 尚未建立，AI 必须明确以现有总纲为依据，不能假装读取了不存在的文件。

## 正文最高原则

本书首先向读者展示奇异新世界和林扬的挣扎，不把正文写成生态论文、证据陈列或正确解题过程。

### 商业爽文底线

本书不是文学化末世练习。正文服务于读者追读与商业回报：危险必须凶，死亡必须近，恶人必须坏，林扬必须在场把局面打回来。

本书以连载追读和持续商业回报为直接创作目标。连续性与基本因果是让读者不出戏的底线，不得反过来压低既有的死亡烈度、恶人恶行、残酷选择、主角反击与公开报应；也不以抽象克制、中立姿态或常规道德直觉替用户自行收束冲突。只有重复、无因果、遮住主线，或不能换来可见情绪与剧情回报的血腥和恶意，才需要改写。

- 不把血腥、死亡、尸体、伤口、残缺和污染藏在远处、门后或一句惨叫里；核心物种首次发威必须完成可见的攻击和不可逆后果。
- 允许并鼓励写直接恶人：抢药、抢粮、卖车位、抛伤员、隐瞒感染、背刺和拿弱者换资源。不要为了“复杂”给每个恶人补理由或替其辩护。
- 恶人初次压场或升级时，允许用资源进行当众羞辱：逼人低头换粮、撕掉腕带、抽走病人的药、让人为了家属让位。羞辱必须落到具体受害者和具体损失，紧接林扬的当场清算；不写无关的长期折磨或反复同一种羞辱。
- 恶人承担章节主压力时，不能只写“倒卖、作乱、害人”的结论，必须写出其对具体受害者实施的勒索、诬陷、泄密、背叛、断路、投放污染或谋害动作，以及受害者当场失去什么；恶行与资源、空间和当章冲突相连，随后由林扬夺回人、物资、位置或规则。
- 恶行必须立刻改变场面，并在本场或短期内由林扬强势定局。定局后写清惩罚、夺回的资源、救下的人和新增的威望或权限。
- 配角的专业价值为林扬创造窗口，但不能替主角完成最终惩罚、猎杀、夺回资源或公开立威。
- 不用作者总结宣布残酷；把血、伤口、尸体、门槛、药瓶、车位、武器和人群站位写到现场。

- 底层保持人物位置、伤势、资源、能力和基本因果连续，正文不展示这套检查过程。
- 读者需要看懂人物为何行动，不需要看完观察、证据、推理和结论的完整链条。
- 新生命先可以美、怪、壮观、有用或令人不适，不必一登场就攻击人类。
- 生态链不按“血腥生命加身体恐怖生命”逐项配额；全书同时保留捕食、寄生、竞争、漠不关心和互利共存，前期重点展示物种之间的残酷猎杀。
- 暴力重在动作清楚、后果具体和形式新奇。华丽反差来自生物外形与行为，正文句子仍须通俗直接。
- 开篇核心物种不能只当作环境压力和事故诱因。前三至六章必须尽早完成一次主动、近距离、有物种辨识度的猎杀；未知可以暂不解释机制，不能把接触、肉体破坏和死亡一起藏掉。
- 场景连续、单一压力线、贴身视角和通俗语言不等于降低事件强度。同一麻烦要在场内持续升级并付出代价，不能只增加声音、影子、咳嗽和逼近中的威胁。
- 林扬观察路线、裂缝、花粉和水源，是因为要回家、逃命、救人，或被眼前奇异生命吸引，不是为了给读者证明设定。
- 允许人物听错、误判、冲动、逃避和选择非最优方案；未知可以跨越多章，甚至不完全解释。
- 默认每章最多确认一个新生态结论；首次登场不同时说明物种机制、弱点、研究名和用途。
- 强画面、关键动作和具体后果之后直接推进，删掉“这意味着”“他意识到”式翻译。
- “三次见面”“误读、观察、准备、接触”只用于幕后设计，不得成为正文打卡模板。
- 第三人称限知不只是“不写林扬不知道的信息”，还要让每句现场叙述从他的感官、身体、念头、动作或误解中发生。
- 禁止用外部摄像机先替林扬看清完整现象，再写他的反应；也不用高频“他看见”“他觉得”来假装贴身。
- 信息属实、林扬可知，不等于必须写进本章。只写能改变他当场欲望、注意、身体、动作、选择或关系的信息。
- 每章只让一条主要异常或压力线升级。新闻、群聊、报告、远方消息和新物种不得并列摆证据；不能加深同一异常或改变林扬行动的，延后到下一章。
- 正文只用通俗、直接的现代汉语。普通动作写清谁做了什么，不用陌生搭配、抽象意象、拟人化气味和光线制造小说感；奇异感由新世界本身承担。
- 对白要像普通人在现场说话，允许抢话、重复、说不完整和没听清，不把人物台词修成完整观点或漂亮金句。

正文任务可以统一附加：

```text
底层保持连续性与基本因果，但不要在正文中展示推理链和设定证明。正文只负责让读者贴着林扬经历奇观、欲望、误判、行动、挣扎和后果。

贴近林扬不是用外部摄像机跟拍他。每句现场叙述都必须从他此刻的感官、身体、念头、动作或误解中发生。只报告“他做了什么”也不算贴身，动作要带着他的目的、阻力、身体感或注意变化发生。不先由旁白宣布完整异常、再写他发现；不写他看不见的全景、背影和未察觉的身后动静；不靠句句重复“他看见”“他觉得”来标记视角。

设定可以在大纲中完整存在，正文只写此刻真正撞到林扬身上的部分。信息可知不代表必须写；它必须改变他当前的欲望、注意、身体、动作、选择或关系。每章只维持一条主要异常或压力线；新闻、通知、群聊、报告、远方消息和新物种只能加深它或迫使林扬改变行动，不得并列摆证据。

新物种首次出现不解释完整机制、弱点、研究名和资源用途；每章默认最多确认一个新生态结论。人物允许听错、漏看、冲动和做出非最优选择。

强画面或关键动作已经传达信息时，停在画面上，不追加“这意味着、这说明、显然、由此判断、真正的原因是、换句话说”等总结。写完删除不影响下一步理解的分析句、解释句和证据链。

全文使用通俗、直接的现代汉语。能直接写疼、喘、滑、撞、卡住和灯灭，就不用抽象意象、生造搭配、拟人化气味或光线增加文艺感。比喻只在帮助读者看清形状、距离和动作时保留。对白按普通人在现场的说话方式写，允许重复、没说完和答非所问，不写主题句与可摘抄金句。
```

## 推荐工作流

### 1. 先建卷级约束

写新卷前先确认：

- 时间与地点；
- 核心生存目标；
- 生态阶段和核心物种；
- 林扬当前能力、升级节点、首秀、代价和身份回报；
- 核心配角在本卷的长期价值与冲突；普通同行者无需逐个设计用途；
- 小兑现、中型兑现和卷末公开大兑现；
- 本卷夺回或失去的路线、设施、资源和知识。

### 2. 再做章节卡

章节卡至少记录：

```text
时间地点 / 视角 / 起始状态
本章唯一主目标 / 当场压力
物种痕迹 / 旧经验误判 / 观察来源
准备与失败方案 / 林扬关键动作 / 核心配角必要动作（本章如有）/ 普通同行者即时反应
获得与损失 / 生态后果 / 生理债连续性
章末具体钩子
```

同一生态事件可跨章完成“误读、观察、准备、接触”，不要把它机械压进每一章。

章节卡是幕后连续性账，不要求字段逐项进入正文。生态事件需要产生行动结果，但其机制不必完整闭环。

### 3. 正文串行推进

正文按连续章节串行创作。每一批完成后先检查：

- 上章后果是否接住；
- 人物位置、伤势和同行关系是否连续；
- 食水、装备、车辆、设施和通信是否守恒；
- 林扬是否使用了当前卷允许的能力；
- 物种弱点是否有前置观察，优势是否支付结构代价；
- 专业配角是否真正完成了自己的工作；
- 胜利是否得到可见回报，生理债是否在合适场面结算；
- 章末钩子是否由本章后果自然产生。

检查通过再写下一批，避免把连续性问题积累到整卷末尾。

### 4. 去 AI 味放在事实检查之后

先修事实、因果、动作空间和人物动机，再处理句式。去 AI 味不能删掉：

- 林扬的关键判断与最后接触；
- 物种痕迹、结构代价和生态后果；
- 团队专业分工；
- 明确的胜利、损失、资源与权限变化；
- 生理债和下一章接力。

## 可直接使用的提示词

### 设定一致性审查

```text
请先读取 CLAUDE.md、未知进化_故事总纲.md，并按问题需要读取世界设定、地理路线和物种图鉴。审查【目标文件/主题】与当前设定的一致性。

按严重度优先检查：
1. 时间、人物、能力阶段和七卷顺序；
2. 迁跃的能量来源、结构代价和繁殖速度；
3. 地理路线、交通节点和跨区关系；
4. 物种生态链、弱点来源和资源用途；
5. 人物动机、团队专业价值和主题偏移。

先给出带文件位置的具体问题，再给最小修订方案。不要修改拆分前完整归档。
```

### 设计当前卷章节细纲

```text
使用 webnovel-workflow，读取 CLAUDE.md、未知进化_故事总纲.md 中第【X】卷、当前卷涉及的地理路线、世界阶段和物种条目，为第【起始章】-第【结束章】设计章节细纲。

要求：
- 每章只有一个主要推进目标；
- 每章只有一条主要异常或压力线，新信息必须加深它或改变林扬的当场行动；
- 同一生态遭遇按“痕迹、误判、接触”逐步展示；
- 冲突整体完成“误读、观察、准备、接触”，但不机械要求每章四步俱全；
- 林扬能力严格服从当前卷阶段；
- 核心配角在整段剧情中应有林扬无法长期替代的价值，但不要求每章、每次出场都发挥作用；
- 普通同行者和一次性路人可以没有专业能力、剧情功能、成长线与后续回收，不强行命名、分配技能或安排报恩；
- 记录人物位置、伤势、食水、装备、车辆、通信和生理债；
- 每次胜利产生具体回报和生态后果；
- 章末钩子来自本章因果。

完成后检查与后一阶段的接力，并同步真正受影响的工作文件。
```

### 商业化章节细纲设计

```text
读取 CLAUDE.md、故事总纲中第【X】卷、当前地点环境设定、相关物种条目、已有正文和相邻章节细纲，为《未知进化》第【起始章】-第【结束章】设计或重做商业化章节细纲。目标是让读者持续追读，不把末世写成文学化的环境描写或资源管理记录。

设计前，先从相邻正文和细纲中核对本段必须承接的时间、地点、在场人物、伤势、装备、食水、车辆、通信、能力阶段及已知威胁。这些内容仅作内部核对，不单独创建事实账文件；只有会影响后续章节的变化，才写入对应章节细纲的“处境变化/兑现”或“连续性”字段。发现正文、相邻细纲与高优先级设定冲突时，不得自行选一个版本继续设计；必须向用户列出冲突事实、涉及文件、按 `CLAUDE.md` 判定的优先级结论及最小修复建议，未经用户明确要求不得修改高优先级设定。

每章必须明确写出：
- 林扬此刻最直接的欲望；
- 一个主压力：怪物主动猎杀、环境规则翻转、恶人压迫、资源危机或迫近选择；
- 林扬的压场动作和最终定局；
- 可见收益：救下的人、抢回的药粮武器、获得的路线、钥匙、名单、权限、信任或威望；
- 章末由本章后果自然生出的具体钩子。
- 起始承接：本章开始时必须保留的人物、伤势、装备、资源、能力和已知威胁；
- 连续性：本章新增或改变、下一章必须接住的人员、伤势、物资、路线、能力、情报或社会关系。

额外要求：
- 先依据当前卷确定本段处于哪种叙事阶段：灾变初期重点是未知生命与环境失控；迁徙期重点是路线、补给、车队和地方规则；防线与反攻期重点是夺设施、争地盘、打势力；控制区期重点是产业、权力和更大生态威胁；退潮与终局期重点是保全、取舍、撤离与身份终局。不得把某一阶段的冲突方式硬塞到另一阶段。
- 每两至三章安排一个能让读者记住的环境异化画面，并让当前地点失去一项旧功能。校园、道路、桥隧、车队、水厂、地下空间、城市街区、高原营地都必须被新生态改写；写清门、灯、水、粮、暖气、通风、车辆、道路、设施或避难所怎样反过来害人。
- 任何核心新物种的首次正面猎杀，必须完成“选中活人 -> 身体接触 -> 独有伤害 -> 不可逆后果”。未知只保留机制未知，不能藏住攻击、血、残缺和死亡；非猎杀型物种则必须正面毁掉路线、资源、设施或人类规则。
- 人祸强度服从当前卷阶段和既有细纲：灾变刚开始时，可用不命名、不回收的恐慌自私动作衬托林扬力量、速度和护人本能，不抢怪物主线；当资源、名额、地盘或制度成为卷内主矛盾后，再建立持续恶人或敌对势力。恶意必须压到具体受害者身上，林扬必须在场清算，夺回资源、规则或位置，并得到公开收益。
- 核心配角各自完成专业工作，林扬负责最后距离、公开反击和最终定局；不要用配角替主角收尾。
- 每三至五章至少安排一次符合当前卷阶段的硬兑现：主角反杀、救人、公开立威、夺权、夺资源、能力首秀、夺回设施、打通路线或大规模环境反转。铺垫不能连续两章没有当场回报。
- 允许简化科学解释与局部逻辑，只守住人物位置、伤势、装备、能力阶段和上一章后果；不要为了严密论证压低速度、血腥、主角高光和恶人报应。

完成后用表格列出每章的：起始承接 / 主压力 / 主角定局 / 可见收益 / 环境异化或人祸节点 / 连续性 / 章末钩子，并检查与已有正文、当前卷终点和下一阶段的接力。只修改真正受影响的工作文件，不改拆分前完整归档。
```

### 串行创作正文

```text
请依据项目总规则、对应卷纲、章节细纲、登场物种设定，以及相邻已完成正文，
  串行创作【第X章】至【第Y章】。

  严格按“一章创作 -> 一章复核 -> 修正后再写下一章”的方式执行，不要一次性批
  量写完所有章节，也不要只给细纲或创作计划。

  每章流程：

  正文最低完成定义：
  - 一个章节文件只有在读者脱离细纲也能独立读完一个连续现场时，才算正文。正文必须让主角从正在处理的具体动作进入，写到这件事得到具体结果、明确失败，或被已经发生的变化彻底打断。
  - 每章正文净字数不得少于 2000 个汉字，标题、Markdown 标记和空白不计。字数只是不把完整现场写成摘要的最低门槛，不得靠重复动作、空话、设定讲解、无效回忆或拆碎短段凑字数；低于下限即判定未完成。
  - 不得用“到了某地、遇到危险、主角解决、拿到物品”一类概述，替代转场、冲突升级、人物反应、伤害余波与结果落地。达到字数后仍必须承载本章一个主麻烦的发生、升级、接触、后果和下一章入口。
  - 细纲承载不住完整现场时，应拆细纲、延后事件或扩展当前场面；不得把摘要、场景说明、事件串列或待扩写稿保存为正文，更不得以已创建章节文件代替已完成正文。

  正文交付门禁（不可跳过）：
  - 每章写完后，必须对当前文件执行 `tail -n +2 "正文文件" | rg -oP '\p{Han}' | wc -l`，以 Unicode 汉字数作为唯一字数口径。标题、Markdown 标记、空白、标点、数字和英文均不计入；禁止使用 `wc -m`、去空白总字符数、编辑器估算字数或人工估算替代。
  - 命令结果少于 2000 时，本章状态只能是“未完成”，必须继续扩展或重写当前章；不得进入下一章，不得开始下一章的读取、规划或创作，不得提交，也不得在报告中称其为“正文”“完成”“通过”或“已复核”。
  - 字数达到 2000 不是放行条件。动作链、人物位置、伤势、装备、对白、物种信息、章末接力和文风任一项存在已知问题时，仍判定本章未完成；必须先修正当前章、重新执行字数命令和完整复核，再允许进入下一章。
  - 不得把“先写场景、以后补字数”当成工作步骤。文件可以在编辑过程中暂时不足字数，但在当前章通过门禁前不得对用户报告阶段成果，更不得把它作为相邻已完成正文继续续写。

  1. 先读取上一章结尾、当前章细纲和下一章的接力需求。同时明确本章给网文读
     者的核心追读兑现是什么：近距离血腥死亡、未知生命主动猎杀、恶人压迫与当
     场清算、主角高光、抢回资源或局势突变。本章可以不把所有类型都写全，但不
     能只有铺垫、气氛或克制的观察。若出现恶人，必须让其行为压到具体受害者身
     上，并由林扬在场打断、惩罚或夺回利益。读取细纲
     后先在内部区分“必须守住的事实与结果”和“仅供设计参考的展示方式”；细纲
     中的字段顺序、概括句、形象说法和事件列举都不是正文段落顺序。
  2. 在不输出计划的前提下，先按现场划分本章。一个现场只围绕主角眼前的一件
     麻烦：从他正在处理的动作进入，直到这个动作得到具体结果、失败，或被一个已
     经发生的变化彻底打断，再进入下一个现场。下一个现场必须从前一个现场末尾的
     人物位置、身体状态、物件或新变化自然长出来，不能为了完成细纲节点突然切到
     新地点、新危机或新人物。场景连续只约束画面如何衔接，不限制事件强度；同一
     麻烦应从出现、逼近继续升级到接触、伤害、失败或代价，不能反复增加细节却让
     局势不变。进入新现场时，用主角当下会注意的最少信息建立空间轴：入口、出口、
     障碍、相对远近、移动方向，以及关键人物分别站在哪一侧。人物移动、追逐、搬运、
     开关门和上下楼必须从上一刻的位置发生；穿过门、水帘、拐角、楼层或拥挤人群后，
     若站位已经改变，应借动作或物件重新锚定方向。不要画平面图式介绍场地，但要让
     读者能够判断人物从哪里到哪里、动作是否够得着、失败会堵住谁。
     新场景不是现场清单：不按床位、人物、伤势、物资逐项扫过一遍。只写主角眼下
     要处理的对象、会挡住行动的障碍，以及会立刻改变选择的人或物；某人的伤势、
     位置或物品若删掉后当前动作仍清楚，就等它真正影响救援、移动、争夺或选择时
     再带出。空间信息服务于行动，不写成场景说明书。
  3. 只创建当前这一章正文，保持贴近主角的第三人称限知视角。宁可少写一个细纲
     事件、延后到下一章，也不要把关光、逃跑、遇人、发现新物种、能力首秀、路线
     选择等多个完整画面挤进同一章或同一场面。不要把细纲逐条改写成正文，也不要
     给每个细纲字段各写一段。正文可以合并事件、改变展示顺序、省略过渡节点，或
     把不影响本章因果的内容延后；只要守住人物状态、必要事实、核心结果和下一章
     接力即可。每一段都必须由主角上一刻的动作、阻碍或现场变化逼出来，不能因为
     “细纲里还有一项没写”就突然切换画面、安排对白或补一段说明。
     段落以一个连续动作、同一注意目标或一次局势变化为基本单位，不把每个普通句子
     都拆成单独一段。同一人物围绕同一目标连续观察、移动和操作时，应合成自然段；
     只有新危险落地、力量或判断突变、明确死亡、不可逆选择和章末钩子等真正需要停
     顿的落点，才优先使用短段或单句段。段落长短应随现场松紧自然变化，不用连续短
     段制造虚假紧张，也不把多个动作阶段塞进一个难以辨认站位的长段。
     专业名词、设备和药物首次进入正文时，优先使用读者熟悉的俗称；必须保留专业词
     时，用外形、用途或人物操作顺手说明，不写定义和知识讲解。
     动作描写先求准确、直观和符合日常表达。普通环境与生理现象使用和主体
     自然匹配的常用动词，不为制造小说感强行加重力度。同一段只突出一个动作
     重点，强动词优先留给真正的威胁、冲突和人物反应；避免让水、光、气味、声音、
     泡沫等普通事物在同段中连续拟人化“发力”。能直接写可见结果时，就写清谁
     做了什么、出现什么、导致什么，不让炫技搭配抢过事件本身。
     避免刻意动词不等于机械替换已经自然、准确的感官表达。改词前先核对词义、
     身体状态和前后因果；如“胃里烧得发紧”能够直观传达饥饿或胃酸感，就不应为
     避开“烧”改成含义不同的“抽紧”或“抽搐”。
     通俗直接不等于尽量省字，短句和快节奏也不能破坏现代汉语的语法完整与自然
     口吻。动词单独使用不自然，或必须依靠方向、结果和对象才能看清动作时，应补
     全必要的宾语、补语或惯常搭配；不得把“挣扎”截成孤立的“挣”，也不把“挣
     开、挣脱、推开、退回”等有明确方向或结果的动作压成含糊单字。
     “不写解释”只禁止设定讲义、作者总结和强画面后的重复翻译，不得借此删去让
     现场成立的因果。观察、联系、试探、防守等动作收束时，不得孤立用“又消失”
     “没再碰”“没人再问”“没有回头”一类结论式短语替人物或画面下结论；应写出
     导致结果的具体动作、对象和紧接着的可见变化。只有前文已明确重复行为和必要
     结果时，才可简写。
     危机中的移动、拉扯、支撑、躲避和攻防必须写清“具体身体部位或工具
     -> 相对哪个人或物 -> 朝哪个方向行动 -> 人物或物体出现什么可见结果”。
     不得用“身体也跟着挤进去一点”、“往那边退”、“顺势一带”等缺少身体
     部位、参照物、方向或结果的泛化动作连接前后句。“进去、出来、过去、回来、
     往里、往外、跟着、挪动、退、一点、一下”等词可以使用，但必须让读者不用
     依靠作者脑内空间图就能立即定位。为了清楚，可以重复“肩膀、门板、门缝”
     等具体名词，不要为避免重复换成“身体、那里、里面”。修改某个危机节点时，
     从人物上一个稳定站位连续回读到下一个稳定站位，不只给原句叠加新压力，
     却留下旧稿中含糊的动作连接。
     神态描写只落在认出熟人、开口求助、目睹死亡、能力暴露、关系变化、作出
     残酷选择及承受选择后果等真正改变人物状态的节点。神态必须由人物眼前的
     刺激引起，并影响紧接着的动作、对白、信任或决定；若删掉后人物和局势都
     没有变化，就不为“画面丰富”单独添加。优先写视线停在哪里、嘴唇是否能
     说出话、表情如何被下一步动作打断，以及人物是否避开或接住另一个人的目光，
     使用通俗、可见的短反应，不用“眸光一沉、瞳孔骤缩、神色复杂、眼底闪过”
     等模板替人物表演情绪。人物连续逃命、搬运或攻防时，不在每个动作之间插入
     表情；原有抓握、停顿、盖住尸体、让路或挡门等动作已经能表现情绪时，也不
     再追加“他很震惊、她很悲伤”的解释。贴近林扬的限知视角下，不从外部完整
     描写他自己的脸；改写他当时能感到的停顿、视线、牙关、呼吸和手上动作，
     其他人物的神态只写林扬现场能够看见的部分。
     危机场面使用通俗、简单、直接的现场语言，不先写“情况更糟了”、“门内
     也有人开始咳”、“已经晚了”等概括句，再用下一段举例。读者可以暂时
     不知道危险的来源、机制和下一步变化，但必须当场看清“谁或什么在哪里
     -> 正在攻击或阻挡谁 -> 造成什么身体或空间结果 -> 人物被迫马上做什么”。
     视角内已经能看见的攻击、伤口、死亡、位置变化和倒计时不为制造悬念而藏掉，
     也不让读者通过声音、影子、人物反应或作者评价额外推断这一秒发生了
     什么。悬念来自“下一步能不能活”，不来自“上一句究竟写了什么”。
     若本章承担前期核心物种首次正面威胁，必须让该物种成为行动者，而不是气味、
     粉尘、声音、黑影或踩踏事故的背景。至少完整写出一次“靠近或选择活人 -> 发
     生身体接触 -> 以该物种独有方式破坏肉体 -> 留下不可逆后果”的动作链。机制
     和来源可以继续未知，已经发生的扑击、穿刺、吸血、撕裂、寄生或死亡不能含蓄
     带过、移到门外或只用惨叫交代。
     若死亡承担威胁首次兑现、救援失败或人物转折，必须在现场写清“致死伤害
     -> 不可逆的身体结果 -> 死亡如何继续影响活人”。“胸口不再起伏”、
     “身体软下去”、“手松开”只能作为过程细节，不得单独替代死亡画面。
     相邻章节或同一场面的多次死亡不得复用同一套委婉模板：应按伤害部位、
     物种结构、尸体变化和目击者当场接触分开设计。末世类型烈度不因“文学
     克制”或道德顾虑被主动调低；句子仍须通俗准确，不用堆砌血腥形容词和无
     因果的肉体奇观冒充残忍。
  4. 写完立刻复核本章：
     - 是否从主角正在处理的具体麻烦进入；
     - 是否只有一条主要压力线；
     - 是否已经实际执行 `tail -n +2 "正文文件" | rg -oP '\p{Han}' | wc -l` 并记录命令输出；Unicode 汉字数是否不少于 2000。不得把 `wc -m`、去空白字符数或估算值写成净汉字数；任何不足下限的章节均直接判定未完成，不得以“短章”“节奏快”或“下一章会补”通过；
     - 若本章字数、动作链、连续性、对白或文风任一项未通过，是否已停止在当前章修正，而没有读取、规划、创作、报告或提交下一章；
     - 本章是否达到“正文最低完成定义”：脱离细纲后，读者能否独立读完一个连续、可感知的现场，而不是只读到地点、危险、处理和结果的顺序概述；
     - 是否出现伪正文：连续用概述句跳过转场、冲突升级、人物反应、伤害后果或结果落地；若本章能够被压缩成几条细纲事件，或正文段落与细纲字段一一对应，判定不通过，必须重写，不得进入下一章；
     - 正文是否已经脱离章节细纲的条目结构，成为主角连续经历的现场；如果段落能
       与“目标、异常、核心推进、处境变化、章末钩子”等字段一一对应，说明仍是
       细纲扩写，必须重新组织；
     - 是否为了交付细纲中的每个节点而塞入多余场面、转场、人物台词或设定说明；
       能延后、合并或不展示的内容是否真正舍弃；
     - 本章是否真的兑现了一项值得继续追读的内容：血腥死亡、怪物主动猎杀、恶人
       被清算、主角反杀、救人或资源回报，而不只是为以后铺垫；删除本章
       后如果只少了一段移动、气氛或“危险越来越近”，说明强度不足；
     - 每个场面是否真正停留到当下动作完成或被打断，而不是刚看清一个画面就跳去
       交付下一个细纲事件；
     - 同一场面的压力是否改变了人物身体、位置、物件、选择或生死，而不是只增加
       翅响、影子、咳嗽、围观和更近的距离；
     - 场面转换时，读者是否能跟着主角看清从哪里到哪里、谁还在身边、手上拿着什
       么、前一刻发生的事怎样逼出下一步；
     - 新现场是否用最少信息建立了入口、出口、障碍、方向和人物站位；门内门外、
       走廊两端、楼层高低及移动后的相对位置是否始终一致，动作距离是否真实可执行；
     - 新场景是否把床位、人物、伤势、物资或环境逐项盘点，形成与当前麻烦无关的
       场景说明书；每项信息是否立刻影响主角的动作、障碍或选择，不能影响的是否
       已延后到真正需要它的动作节点；
     - 每个关键移动、拉扯、支撑、躲避和攻防句是否写明具体身体部位或工具、
       参照的人或物、行动方向及可见结果；是否因为避免名词重复，反而换成了“身体、
       里面、那边”等含糊指代；
     - 对关键动作执行“孤立句测试”：只连着前一句阅读时，是否能立即回答“谁在
       动、用什么部位或工具、相对什么朝哪里动、动完什么变了”；任何一项需要
       依靠作者脑内地图才能补全，就必须重写；
     - 对本次新增或改写的每一句动作、环境与伤害描写再做一次专项复核，不因它
       只服务环境异化、小人性阻碍或局部气氛就跳过。植物、根须、粉尘、水、血、
       光和声音应写成主角当场能确认的状态或明确后果；若它们正在运动，必须交代
       读者可见的动作方式、参照物和结果。任何句子只靠“挤、爬、涌、歪、红色”
       等模糊词让读者猜过程，或会误导读者把静态生长理解为当场主动移动，都必须
       改成清楚的状态、身体部位、相对位置或物体结果；
     - 认人、求助、死亡、能力暴露、关系变化和不可逆选择前后，核心人物是否有
       足以让读者看清其恐惧、迟疑、信任或决断的神态及动作反应；这些反应是否
       直接承接现场刺激并逼出下一步，而不是孤立的表情标签；
     - 是否为了增加神态而频繁写互相看一眼、眼神变化、脸色变化，打断正在发生的
       危机动作；同一人物与不同人物的反应是否有所区别，已有动作能够传达情绪时，
       是否删除了重复解释和套话；
     - 段落是否按连续动作、注意目标和局势转折组织；是否把本可连写的普通句子拆成
       连续短段或单句段，又是否把多个动作阶段挤成一个失去节奏与空间辨识度的长段；
     - 是否所有画面、判断、动作都贴着主角当场感受发生；
     - 是否避免旁观者全景、作者总结、设定讲解、证据链和 AI 式论证；
     - 是否使用通俗直接的描写与对白，不写文青式比喻和漂亮话；
     - 普通环境和生理现象的动词是否准确、常用；同一段是否连续用强动词或
       拟人化搭配给每句加力，以致措辞抢过威胁、伤害和结果本身；
     - 是否把原本自然、准确的感官表达机械换成陌生或含义不符的词；改词后是否仍
       与人物当下的身体状态、前后因果一致；
     - 是否为了短句和省字删掉了必要的宾语、补语、动作方向或结果；是否存在必须
       让读者自行补字才能读顺的孤立动词、残缺搭配或不自然省略；
     - 是否把“少解释”误作删掉现场因果，并孤立使用“又消失”“没再碰”“没人再
       问”“没有回头”等结论式短语替人物或画面收束；这些句子是否已改为导致结
       果的具体动作、对象和紧接着的可见变化，或确有前文已明确的重复行为与结果
       可支撑简写；
     - 是否把“通俗、克制、近视角、场景厚度”误写成平淡；句子可以朴素，事件必
       须保留应有的暴力、猎奇、恐怖和冲击；
     - 危机是否直接写明了危险主体、受害者、当场动作、身体或空间结果与迫在
       眼前的选择；是否仍在用“有人开始咳”、“情况更糟”等概括过渡要求读者
       自行补画面；
     - 视角内已经发生的伤害、位置变化和倒计时是否被故意含糊；删掉概括句后，
       读者是否仍能立即看清这一秒发生了什么、下一秒为什么必须行动；
     - 核心新物种是否亲自行动并造成有辨识度的伤害；血腥是否来自它的身体结构和
       捕食方式，而不是主要由踩踏、桌椅、门板和远处惨叫代替；
     - 未知感是否只保留未知机制，而没有藏掉读者此刻应看到的攻击、人体损伤与死
       亡兑现；
     - 关键死亡是否仅用“胸口不动”、“身体软下去”、“手松开”等通用委婉句
       收尾；是否看清了致死伤害、不可逆身体结果及其对活人的当场影响；
     - 相邻死亡是否复制了同一生理停止模板；每一次是否由不同伤害部位、物种
       机制、尸体变化或目击者接触获得独立记忆点；
     - 对白是否只来自人物当场要人、要路、要药、要自保或失控的反应，而不是替作
       者报方向、解释风险、介绍人物、切换场景或替下一章摆钩子；
     - 是否删掉了过于准确、轮流接话、恰好说出局势结论的台词；危机中的人可以听
       错、重复、说半句、不回答，能用动作、位置和物件写清的事不让角色再说一遍；
     - 是否让配角通过当场行动存在，而不是轮流发表观点；
     - 是否与前章的人物位置、伤势、装备、资源、时间和物种信息连续；
     - 是否准确把新的动作、风险或选择交给下一章。
  5. 发现问题时，先修改当前章，再进入下一章；不要带着已知问题继续写。
  6. 当前章复核通过后，自动创作下一章，重复上述流程，直到完成指定范围。

  正文优先写主角此刻想做什么、眼前有什么阻碍、他如何行动、行动造成什么后
  果。新世界和新物种应通过主角亲历的画面、身体反应和实际损失进入，不要为了
  展示设定而堆砌信息。章节细纲只规定必须守住的事实和结果，不规定正文必须逐项
  展示，也不规定段落顺序、场面数量和对白内容。正式正文不是章节细纲的扩写版；
  应先让一个画面在主角眼前成立，再由画面本身把他推到下一个画面。即使因此少写
  一个细纲节点，也比把多个节点依次交付、破坏现场感更好。
  贴近主角不等于把最狠的部分挡在视野外，未知也不等于只写危险接近。尤其在开篇
  阶段，应让主角近距离看见、碰到并处理新物种造成的血、伤口、尸体与救援失败；
  同时让恶人把药、粮、车位和弱者当作筹码，再由林扬以行动把人和资源抢回来。读
  者要先确认这个世界会杀人、也会逼人作恶，并确认林扬能让作恶者付出代价，再逐
  步揭开它为什么这样运转。

  全部章节完成后，只简要报告：
  - 创建的正文文件；
  - 每章实际执行的 Unicode 汉字计数命令及输出，以及是否达到 2000 字下限；
  - 每章的核心推进；
  - 每章的追读兑现，以及核心新物种是否完成主动、可见、有辨识度的伤害；
  - 连续性与文风复核结果；
  - 是否存在未提交改动。

  提交门槛：
  - 每一章均已达到“正文最低完成定义”，有实际 Unicode 汉字计数输出不少于 2000，并完成完整复核、修正发现的问题后，才可以提交本地仓库；
  - 任一章节未执行计数命令、计数不足 2000、仍是概要稿、细纲扩写、未完成场景，或仍有已知的动作链、连续性、对白或文风问题时，整批不得提交；
  - 提交前执行 `git diff --check`。最终报告只能列出已同时通过字数门禁和完整复核的章节；存在任何未完成章节时，必须明确报告文件名、实际汉字数与阻塞项，不得使用“全部完成”“正文已完成”“复核通过”或类似表述。
```

```text
使用 novel-de-ai 和 human-prose，修订正文第【起始章】-第【结束章】。先读前一章、目标章节、后一章以及对应细纲和必要设定。

先锁定不可误改的剧情事实：路线、人物在场、伤势、装备、食水、车辆、通信、林扬能力阶段、物种痕迹与弱点、胜利回报、生理债和章末钩子。

重点修复作者总结、证据链、过度逻辑、伪科学讲义、观察清单、设定预告片、并列钩子、群众整齐反应、过度从容、比喻炫技、高频短句和角色同声同气。先写明林扬当前的欲望和本章唯一的主要异常，删除不能加深它、阻碍行动或改变选择的素材。优先直接删除本章行动不需要的解释；必要信息才用动作、物件、失败、专业分歧和人物当场利益少量带出，不擅自新增剧情。
```

## 番茄草稿箱上传工具

本项目提供一个浏览器自动化工具，用于把根目录 `正文/` 下的正文章节保存到番茄小说作者后台草稿箱。

> 注意：`fanqie_draft_upload/fanqie_publish.yaml` 当前仍保留上一作品的 `book_name` 和后台地址。在取得《未知进化》的作品 ID 并人工更新配置前，不要执行远端保存命令。

功能边界：

- 只保存草稿，不发布、不定时发布、不提交审核。
- 不在项目中保存账号、密码、cookie 或 token。
- 浏览器登录状态保存在仓库外，具体路径以 `fanqie_publish.yaml` 为准。
- 工具只读取 `正文/` 并写入本地状态台账，不移动、不改写小说创作文件。

相关文件集中在：

```text
fanqie_draft_upload/
├── fanqie_prepare_manifest.py      # 生成/刷新章节状态台账
├── fanqie_publish_browser.py       # 打开番茄后台并保存草稿
├── fanqie_publish.yaml             # 番茄后台地址、选择器、路径与安全配置
├── requirements.txt                # Playwright/PyYAML 依赖
└── data/fanqie_publish_state.json  # 本地章节状态台账，不提交
```

### 安装依赖

```bash
pip install -r fanqie_draft_upload/requirements.txt
python3 -m playwright install chromium
```

### 首次登录番茄后台

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py login
```

脚本会打开浏览器。请手动完成番茄作者后台登录、验证码、短信或滑块验证。

### 生成或刷新章节台账

```bash
python3 fanqie_draft_upload/fanqie_prepare_manifest.py
```

默认读取根目录 `正文/`，生成：

```text
fanqie_draft_upload/data/fanqie_publish_state.json
```

如果某章已标记为 `draft_saved`，但本地正文 hash 已变化，脚本会停止并要求先人工确认远端草稿，避免覆盖不明状态。

### 检查后台页面

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py check
```

用于确认脚本能进入对应作品的章节管理/草稿箱页面。

### 审核待上传章节

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py audit
```

该命令只读取本地状态台账，输出各状态章节数量和章节范围，不会打开远端保存草稿。

### 保存章节到番茄草稿箱

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py save-drafts --confirm-save-drafts
```

常用范围参数：

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py save-drafts --start 1 --end 10 --confirm-save-drafts
python3 fanqie_draft_upload/fanqie_publish_browser.py save-drafts --only-chapter 12 --confirm-save-drafts
python3 fanqie_draft_upload/fanqie_publish_browser.py save-drafts --limit 3 --confirm-save-drafts
```

真正写入远端草稿箱前，脚本还会要求输入确认语，例如：

```text
SAVE FANQIE DRAFTS 1-10
```

确认语不匹配会取消操作。

### 中断后继续

```bash
python3 fanqie_draft_upload/fanqie_publish_browser.py resume --confirm-save-drafts
```

如果出现 `draft_saving` 遗留状态，应先人工确认番茄后台草稿是否已保存，再手动把对应章节状态改回 `pending` 或标记为 `draft_saved`。

### 日志、截图与本地状态

运行截图和错误截图默认保存在：

```text
fanqie_draft_upload/logs/
```

这些运行产物和本地状态台账已在 `.gitignore` 中忽略，不应提交到仓库。
